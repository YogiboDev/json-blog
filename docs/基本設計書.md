## 2. システム構成

### 2.1 全体構成図

```
[ブラウザ]
    │  HTTP (GET/POST)
    ▼
[Express アプリケーション (server.js)]
    │  ルーティング処理
    ▼
[データアクセス層 (lib/db.js)]
    │  fs.readFileSync / writeFileSync
    ▼
[JSONファイル (data/posts.json, data/comments.json)]

画面描画: EJSテンプレート (views/*.ejs) + 静的CSS (public/css/style.css) + TinyMCE (セルフホスト静的配信)
```

### 2.2 技術スタック

| レイヤー | 技術 |
|---|---|
| 実行環境 | Node.js (v22系) |
| Webフレームワーク | Express 4系 |
| テンプレートエンジン | EJS 3系 |
| リッチテキストエディタ | TinyMCE 8系（セルフホスト） |
| データストア | JSONファイル（ファイルシステム） |
| スタイル | 素のCSS（フレームワーク不使用） |

### 2.3 ディレクトリ構成

```

├── server.js              … エントリポイント・ルーティング定義

│   └── auth.js              … 固定ID・パスワードによるログイン判定、Cookieセッションの発行・検証
```

## 3. 画面一覧

| 画面ID | 画面名 | URL | 概要 |
|---|---|---|---|
| SCR-01 | 記事一覧画面 | `GET /` | 全記事を新着順に一覧表示 |
| SCR-02 | 新規投稿画面 | `GET /new` | 記事投稿フォーム（TinyMCEリッチテキストエディタ。未ログイン時はSCR-11へリダイレクト） |
| SCR-03 | 記事詳細画面 | `GET /posts/:id` | 記事本文（リッチテキスト）とコメント一覧・コメント投稿フォーム |
| SCR-04 | 検索結果画面 | `GET /search` | キーワードに一致した記事一覧（一覧画面を流用） |
| SCR-05 | カレンダー画面 | `GET /calendar` | 月別カレンダーと、選択日の記事一覧 |
| SCR-06 | 404画面 | 該当URLなし時 | 存在しないページへのアクセス時に表示 |
| SCR-07 | カテゴリー一覧画面 | `GET /categories` | 全カテゴリーと記事件数の一覧 |
| SCR-08 | カテゴリー別記事一覧画面 | `GET /categories/:category` | 指定カテゴリーに属する記事一覧（一覧画面を流用） |
| SCR-09 | タグ一覧画面 | `GET /tags` | 全タグと記事件数の一覧 |
| SCR-10 | タグ別記事一覧画面 | `GET /tags/:tag` | 指定タグが付与された記事一覧（一覧画面を流用） |
| SCR-11 | ログイン画面 | `GET /login` | ID・パスワード入力フォーム |

## 5. 機能一覧とエンドポイント対応

| 機能 | HTTPメソッド | パス | 対応画面/処理 |
|---|---|---|---|
| 記事一覧表示 | GET | `/` | SCR-01 |
| 新規投稿フォーム表示 | GET | `/new` | SCR-02（ログイン必須） |
| 記事投稿 | POST | `/posts` | SCR-02（ログイン必須）。登録後 SCR-03 へリダイレクト |
| 記事詳細表示 | GET | `/posts/:id` | SCR-03 |
| コメント投稿 | POST | `/posts/:id/comments` | 登録後 SCR-03 へリダイレクト |
| 記事削除 | POST | `/posts/:id/delete` | 削除後 SCR-01 へリダイレクト |
| 検索 | GET | `/search` | SCR-04 |
| カレンダー表示 | GET | `/calendar` | SCR-05 |
| カテゴリー一覧表示 | GET | `/categories` | SCR-07 |
| カテゴリー別記事一覧表示 | GET | `/categories/:category` | SCR-08 |
| タグ一覧表示 | GET | `/tags` | SCR-09 |
| タグ別記事一覧表示 | GET | `/tags/:tag` | SCR-10 |
| ログイン画面表示 | GET | `/login` | SCR-11 |
| ログイン処理 | POST | `/login` | 成功時は`redirect`パラメータ（既定`/`）へリダイレクト、失敗時はSCR-11を再描画 |
| ログアウト処理 | POST | `/logout` | 処理後 SCR-01 へリダイレクト |
| 該当なし | ALL | 上記以外 | SCR-06（404） |

## 6. データ設計（論理設計）

### 6.1 記事（Post）

| 項目名 | 型 | 必須 | 説明 |
|---|---|---|---|
| id | string | ○ | 記事の一意識別子（連番の文字列） |
| title | string | ○ | 記事タイトル |
| content | string | ○ | 記事本文（TinyMCEで作成されたリッチテキストHTML） |
| author | string | ○ | 投稿者名（省略時「匿名」） |
| date | string(ISO8601) | ○ | 投稿日時 |
| category | string | ○ | カテゴリー（省略時「未分類」）。1記事につき1つ |
| tags | string[] | － | タグの配列（0件可） |

### 6.2 コメント（Comment）

| 項目名 | 型 | 必須 | 説明 |
|---|---|---|---|
| id | string | ○ | コメントの一意識別子（連番の文字列） |
| postId | string | ○ | 紐づく記事のid |
| name | string | ○ | 投稿者名（省略時「匿名」） |
| message | string | ○ | コメント本文 |
| date | string(ISO8601) | ○ | 投稿日時 |

### 6.3 データ間の関連

```
Post (1) ────< (0..n) Comment
  posts.json[].id  ==  comments.json[].postId
```

外部キー制約はJSONファイルのため存在せず、アプリケーション側（`lib/db.js`）で整合性（記事削除時のコメント連動削除など）を担保する。

## 7. 非機能設計方針

| 項目 | 方針 |
|---|---|
| セキュリティ（XSS対策・HTML描画） | 記事詳細画面（`post.ejs`）ではTinyMCEで作成されたリッチテキストHTMLを`<%- post.content %>`で非エスケープ描画する。タイトル・投稿者名・コメント本文・タグ・カテゴリー・検索クエリ等の入力値はEJSの`<%= %>`（自動エスケープ）で出力しXSSを防止する。一覧の抜粋（`stripHtml`）や検索処理ではHTMLタグを除去した平文テキストを処理する |
| セキュリティ（ログイン） | ID・パスワードは`lib/auth.js`内の固定値と比較して認証する。ログイン状態は`HttpOnly`・`SameSite=Lax`のCookieで保持し、DB・ファイルへのセッション永続化は行わない |
| データ整合性 | 記事削除時にはコメントも同時に削除するロジックを`lib/db.js`に集約する |
| 可搬性 | ローカルファイルシステムのみに依存し、外部ミドルウェアを必要としない |
| 保守性 | ルーティング（server.js）とデータアクセス（lib/db.js）を分離し、EJSテンプレートで表示ロジックを分離する三層構成とする。認証ロジックも`lib/auth.js`として分離する |
| エラー処理 | 存在しない記事IDへのアクセス、必須項目未入力の投稿は、それぞれ404画面／入力画面へのエラーメッセージ再表示で対応する |
