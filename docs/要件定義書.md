## 2. システム概要

本システムは、データベースサーバーを用いず、JSONファイルをデータストアとして利用するシンプルなブログシステムである。記事の閲覧・投稿に加え、読者とのコミュニケーション手段としてコメント機能、記事を探すための検索機能・カレンダー機能・カテゴリー機能・タグ機能を提供する。記事投稿は固定ID・パスワードによるログインを行った利用者のみが行える。

## 3. 背景・目的

- 個人・小規模チームが手軽に運用できる、DB不要の軽量なブログ基盤を用意する。
- 記事データをJSONファイルで管理することで、バックアップ・移植・目視確認を容易にする。
- 読者からのフィードバックを受け取れるよう、コメント機能を備える。
- 過去記事へのアクセス性を高めるため、キーワード検索と日付（カレンダー）からの記事検索を提供する。

## 4. 用語定義

| 用語 | 定義 |
|---|---|
| 記事（Post） | ブログに投稿される1件の投文。タイトル・本文・投稿者・投稿日時・カテゴリー・タグを持つ |
| コメント（Comment） | 特定の記事に紐づく読者からの投稿。投稿者名・本文・投稿日時を持つ |
| カテゴリー | 記事を分類するための単一のラベル。1記事につき1つのみ付与され、未指定時は「未分類」となる |
| タグ | 記事を分類するためのラベル。1記事に複数付与可能 |
| データストア | 本システムにおいてはJSONファイル（`data/posts.json`, `data/comments.json`）を指す |

補足：カテゴリーとタグはいずれも記事分類のためのラベルだが、カテゴリーは1記事に1つ（大分類）、タグは1記事に複数（自由な小分類）という違いを持つ。

## 5. 利用者・想定利用シーン

| 利用者 | 説明 |
|---|---|
| 投稿者（管理者） | 記事の作成・削除を行う。新規投稿画面の利用にはログインを必須とする（固定のID・パスワードによる単一管理者アカウント） |
| 読者（訪問者） | 記事の閲覧、キーワード検索、カレンダーからの記事検索、コメント投稿を行う |

## 6. 機能要件

### 6.1 記事管理機能

| ID | 要件 |
|---|---|
| F-01 | 利用者は記事一覧をトップページで閲覧できること。一覧は投稿日時の新しい順に表示する |
| F-02 | 一覧には記事タイトル・投稿日時・投稿者・カテゴリー・タグ・本文の抜粋・コメント数を表示すること |
| F-03 | 利用者は記事タイトルをクリックし、記事詳細（全文）を閲覧できること |
| F-04 | 利用者は新規投稿フォームからタイトル・本文・投稿者名・カテゴリー・タグを入力し、記事を投稿できること |
| F-05 | タイトルおよび本文が未入力の場合は投稿を拒否し、エラーメッセージを表示すること |
| F-06 | 投稿者名を省略した場合は「匿名」として保存すること |
| F-09 | カテゴリーを省略した場合は「未分類」として保存すること |
| F-07 | 記事詳細画面から当該記事を削除できること。削除時は確認ダイアログを表示すること |
| F-08 | 記事を削除した場合、その記事に紐づくコメントも合わせて削除すること |

### 6.2 コメント機能（読者とのコミュニケーション）

| ID | 要件 |
|---|---|
| F-10 | 利用者は記事詳細画面でその記事に対するコメント一覧を閲覧できること（投稿日時の古い順） |
| F-11 | 利用者はコメント投稿フォームから名前（任意）・コメント本文（必須）を入力し投稿できること |
| F-12 | コメント本文が未入力の場合は投稿を拒否し、エラーメッセージを表示すること |
| F-13 | 名前を省略した場合は「匿名」として保存すること |
| F-14 | 記事一覧・カレンダー等の一覧表示箇所では、各記事のコメント件数を表示すること |

### 6.3 検索機能

| ID | 要件 |
|---|---|
| F-20 | 利用者はヘッダーの検索ボックスにキーワードを入力し、記事を検索できること |
| F-21 | 検索対象はタイトル・本文・カテゴリー・タグとし、大文字小文字を区別しない部分一致検索とすること |
| F-22 | 検索結果は一覧形式で表示し、該当件数0件の場合はその旨を表示すること |
| F-23 | キーワード未入力での検索実行時は、キーワード入力を促すメッセージを表示すること |

### 6.4 カレンダー機能

| ID | 要件 |
|---|---|
| F-30 | 利用者は月単位のカレンダーを閲覧できること |
| F-31 | カレンダー上の各日付には、その日に投稿された記事件数を表示すること |
| F-32 | 投稿が存在する日付はリンクとして機能し、クリックするとその日の記事一覧を表示すること |
| F-33 | 前月・翌月への遷移ができること |
| F-34 | 本日の日付は視覚的に強調表示すること |

### 6.5 カテゴリー機能

| ID | 要件 |
|---|---|
| F-40 | 利用者はカテゴリー一覧画面で、登録済みの全カテゴリーとそれぞれの記事件数を閲覧できること |
| F-41 | カテゴリー一覧は記事件数の多い順（同数の場合はカテゴリー名の昇順）に表示すること |
| F-42 | 利用者はカテゴリー名をクリックし、そのカテゴリーに属する記事の一覧を閲覧できること |
| F-43 | 記事一覧・記事詳細・カレンダー等の一覧表示箇所では、各記事のカテゴリーを表示し、カテゴリー別記事一覧へのリンクとして機能すること |
| F-44 | 該当カテゴリーの記事が0件の場合はその旨を表示すること |

### 6.6 タグ機能

| ID | 要件 |
|---|---|
| F-50 | 利用者はタグ一覧画面で、登録済みの全タグとそれぞれの記事件数を閲覧できること |
| F-51 | タグ一覧は記事件数の多い順（同数の場合はタグ名の昇順）に表示すること |
| F-52 | 利用者はタグ名をクリックし、そのタグが付与された記事の一覧を閲覧できること |
| F-53 | 記事一覧・記事詳細等の一覧表示箇所に表示される各タグは、タグ別記事一覧へのリンクとして機能すること |
| F-54 | 該当タグの記事が0件の場合はその旨を表示すること |

### 6.7 ログイン機能

| ID | 要件 |
|---|---|
| F-60 | 新規投稿画面（フォーム表示・投稿処理）の利用にはログインを必須とすること。未ログイン状態でアクセスした場合はログイン画面へ遷移させること |
| F-61 | ログインはID・パスワードの入力によって行い、両者が事前に定めた固定値と一致した場合にログイン状態とすること |
| F-62 | ID・パスワードが一致しない場合はログインを拒否し、エラーメッセージを表示すること |
| F-63 | 利用者は任意のタイミングでログアウトし、ログイン状態を解除できること |

## 7. 非機能要件

| 区分 | 要件 |
|---|---|
| 性能 | 想定データ規模（数百記事・数千コメント程度）において、一覧・検索・カレンダー表示は体感1秒以内に応答すること |
| 可搬性 | Node.jsが動作する環境であればOS非依存で動作すること。DBMSのインストールを不要とすること |
| データ保全 | 記事・コメントデータはテキスト形式（JSON）で保存し、目視確認・手動バックアップ・編集が可能であること |
| セキュリティ | 利用者からの入力（タイトル・本文・コメント等）はHTMLエスケープした上で画面表示し、XSS（クロスサイトスクリプティング）を防止すること |
| セキュリティ（ログイン） | ログイン状態はCookieで保持し、`HttpOnly`属性を付与してJavaScriptからのCookie読み取りを防止すること |
| 保守性 | データアクセス処理を共通モジュールに分離し、画面・ルーティングと分離すること |
| 拡張性 | 将来的な複数アカウント対応・ページネーション等の追加を妨げない構成とすること |

## 8. システム構成概要

- サーバーサイド：Node.js + Express
- テンプレートエンジン：EJS（サーバーサイドレンダリング）
- データストア：JSONファイル（`data/posts.json`, `data/comments.json`）
- クライアント：追加のJSフレームワークを用いない、通常のHTML/CSSベースの画面

## 9. 制約事項

- 同時書き込みの排他制御は行わない（小規模・低トラフィックでの利用を前提とする）。
- ID・パスワードは固定値とし、変更にはソースコードの修正を要する。パスワードのハッシュ化・複数アカウント管理・権限レベルの区分は行わない。
- 画像・添付ファイルのアップロード機能はスコープ外とする。

## 10. スコープ外事項

- 複数ユーザーによるアカウント管理（ユーザー登録・権限区分・パスワード変更画面）
- コメントの承認制・スパムフィルタ・通報機能
- 記事の編集機能（削除・再投稿での代替を許容する）
- RSS配信、SNS連携、アクセス解析
- 複数言語対応（本バージョンは日本語UIのみ）
