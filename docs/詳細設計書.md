## 3. データアクセス層（lib/db.js）関数仕様

### 3.1 内部ユーティリティ

| 関数 | 引数 | 戻り値 | 処理内容 |
|---|---|---|---|
| `readJson(file)` | file: string（絶対パス） | Array | ファイルが存在しない／空の場合は`[]`を返す。存在する場合はUTF-8で読み込み`JSON.parse`する |
| `writeJson(file, data)` | file: string, data: Array | なし | `JSON.stringify(data, null, 2)`で整形しUTF-8で同期書き込み |
| `nextId(items)` | items: Array（id保持オブジェクト配列） | string | 既存要素の`id`（数値変換）の最大値+1を文字列で返す。空配列の場合は`"1"` |

### 3.2 記事関連関数

| 関数 | 引数 | 戻り値 | 処理内容 |
|---|---|---|---|
| `getAllPosts()` | なし | Post[] | `posts.json`全件を読み込み、`date`の降順（新しい順）にソートして返す |
| `getPostById(id)` | id: string\|number | Post \| null | 全件から`id`（文字列変換して比較）が一致する1件を返す。なければ`null` |
| `createPost({title, content, author, tags, category})` | 各string | Post | `nextId`でID採番。`title`/`content`は前後空白をtrim。`author`未入力時は`'匿名'`。`category`未入力時は`'未分類'`。`tags`はカンマ区切り文字列をtrim・空要素除去した配列に変換。`date`は`new Date().toISOString()`。`posts.json`に追記して返す |
| `deletePost(id)` | id: string\|number | なし | 該当`id`の記事を`posts.json`から除外して書き戻す。加えて`comments.json`から`postId`が一致するコメントを全て除外して書き戻す（カスケード削除） |
| `searchPosts(query)` | query: string | Post[] | クエリをtrim・小文字化。空文字なら`[]`。各記事の`title + content + category + tags.join(' ')`を結合し小文字化した文字列に対し`includes`で部分一致判定。一致した記事を新しい順（`getAllPosts`基準）で返す |
| `getPostsByDate(dateStr)` | dateStr: string（`YYYY-MM-DD`） | Post[] | `date`の先頭10文字（日付部分）が一致する記事を新しい順に返す |
| `getPostsByCategory(category)` | category: string | Post[] | `(post.category \|\| '未分類') === category`となる記事を新しい順に返す |
| `getCategories()` | なし | `{name, count}[]` | 全記事を`category`（未設定時`'未分類'`）ごとに集計。件数降順、同数はカテゴリー名の昇順（`localeCompare`）でソートして返す |

### 3.3 コメント関連関数

| 関数 | 引数 | 戻り値 | 処理内容 |
|---|---|---|---|
| `getCommentsByPostId(postId)` | postId: string\|number | Comment[] | `postId`が一致するコメントを`date`昇順（投稿順）で返す |
| `addComment(postId, {name, message})` | postId, name: string, message: string | Comment | `nextId`でID採番。`name`未入力時は`'匿名'`。`message`はtrim。`date`は現在時刻ISO文字列。`comments.json`に追記して返す |
| `getCommentCounts()` | なし | Object（`{postId: count}`） | 全コメントを`postId`ごとに集計したオブジェクトを返す |

## 4. ルーティング詳細（server.js）

### 4.1 共通事項

- ミドルウェア：`express.urlencoded({extended: true})`（フォームPOST用）、`express.json()`、`express.static('public')`
- ビューエンジン：EJS（`views`ディレクトリ）
- 共通ヘルパー：`app.locals.formatDate(iso)` — ISO日時文字列を`ja-JP`ロケールの`YYYY/MM/DD HH:mm`形式に整形し、全テンプレートから`formatDate()`として利用可能にする

### 4.2 GET `/` — 記事一覧

| 項目 | 内容 |
|---|---|
| 処理 | `db.getAllPosts()`と`db.getCommentCounts()`を取得し`index.ejs`を描画 |
| 渡す変数 | `posts`, `commentCounts`, `heading: '最新の投稿'`, `emptyMessage: 'まだ投稿がありません。'` |
| 異常系 | 記事0件の場合は`emptyMessage`を表示（エラーではない） |

### 4.3 GET `/new` — 新規投稿フォーム

| 項目 | 内容 |
|---|---|
| 処理 | `db.getCategories()`を取得し、`new-post.ejs`を`error: null`, `categories`で描画 |

### 4.4 POST `/posts` — 記事投稿

| 項目 | 内容 |
|---|---|
| リクエストパラメータ | `title`, `content`, `author`, `tags`, `category`（すべてform-urlencoded） |
| バリデーション | `title`または`content`が空白のみ／未指定の場合、HTTP 400で`new-post.ejs`を`error: 'タイトルと本文は必須です。'`, `categories: db.getCategories()`と共に再描画 |
| 正常系 | `db.createPost()`で登録し、`/posts/:id`（新規記事）へ302リダイレクト |

### 4.5 GET `/search` — 検索結果

| 項目 | 内容 |
|---|---|
| クエリパラメータ | `q`（省略可） |
| 処理 | `q`がtrimして空でなければ`db.searchPosts(q)`を実行、空なら`results = []` |
| 渡す変数 | `posts: results`, `commentCounts`, `heading: '検索結果: 「<q>」'`, `emptyMessage`（`q`の有無で文言を出し分け）, `searchQuery: q`（検索ボックスへの入力値復元用） |
| 描画テンプレート | `index.ejs`（一覧画面を流用） |

### 4.6 GET `/calendar` — カレンダー表示

| 項目 | 内容 |
|---|---|
| クエリパラメータ | `year`, `month`（省略時は当日基準）, `date`（`YYYY-MM-DD`、任意） |
| 処理概要 | ①指定年月の月初〜月末の日数・開始曜日を算出 ②全記事の投稿日ごとの件数を集計 ③各日をセルデータ（`day`, `dateStr`, `count`）として週単位の二次元配列`weeks`に組み立て ④前月・翌月の年月を算出（年またぎを考慮） ⑤`date`パラメータ指定時は`db.getPostsByDate(date)`で該当日の記事一覧を取得 |
| 渡す変数 | `year`, `month`, `weeks`, `prevYear`, `prevMonth`, `nextYear`, `nextMonth`, `selectedDate`, `selectedPosts`, `commentCounts`, `todayStr` |
| 描画テンプレート | `calendar.ejs` |

### 4.7 GET `/posts/:id` — 記事詳細

| 項目 | 内容 |
|---|---|
| パスパラメータ | `id` |
| 処理 | `db.getPostById(id)`で取得。存在しなければHTTP 404で`404.ejs`を描画して終了。存在すれば`db.getCommentsByPostId(id)`でコメント一覧を取得し`post.ejs`を描画 |
| 渡す変数 | `post`, `comments`, `error: null` |

### 4.8 POST `/posts/:id/comments` — コメント投稿

| 項目 | 内容 |
|---|---|
| パスパラメータ | `id`（記事ID） |
| リクエストパラメータ | `name`（任意）, `message`（必須） |
| バリデーション | 記事が存在しない場合はHTTP 404。`message`が空白のみ／未指定の場合はHTTP 400で`post.ejs`を`error: 'コメント内容を入力してください。'`と共に再描画（コメント一覧は最新状態を再取得して渡す） |
| 正常系 | `db.addComment()`で登録し、`/posts/:id#comments`へ302リダイレクト（コメント欄へアンカー遷移） |

### 4.9 POST `/posts/:id/delete` — 記事削除

| 項目 | 内容 |
|---|---|
| パスパラメータ | `id` |
| 処理 | 記事が存在しなければHTTP 404。存在すれば`db.deletePost(id)`でカスケード削除し、`/`へ302リダイレクト |
| UI制御 | 削除ボタン押下時、クライアント側`confirm()`で確認ダイアログを表示（`post.ejs`の`onsubmit`） |

### 4.10 GET `/categories` — カテゴリー一覧

| 項目 | 内容 |
|---|---|
| 処理 | `db.getCategories()`を取得し`categories.ejs`を描画 |
| 渡す変数 | `categories`（`{name, count}[]`） |

### 4.11 GET `/categories/:category` — カテゴリー別記事一覧

| 項目 | 内容 |
|---|---|
| パスパラメータ | `category`（Expressが自動でURLデコード） |
| 処理 | `db.getPostsByCategory(category)`, `db.getCommentCounts()` |
| 渡す変数 | `posts`, `commentCounts`, `heading: 'カテゴリー: 「<category>」'`, `emptyMessage: 'このカテゴリーの記事はまだありません。'` |
| 描画テンプレート | `index.ejs`（一覧画面を流用） |
| 異常系 | 該当記事が0件でもエラーではなく`emptyMessage`を表示（未知のカテゴリー名を指定した場合も同様） |

### 4.12 その他（404）

| 項目 | 内容 |
|---|---|
| 処理 | 上記いずれのルートにも一致しないリクエストは全て`app.use((req, res) => ...)`のフォールバックでHTTP 404・`404.ejs`を描画 |

## 5. 画面詳細設計

### 5.1 共通パーツ（partials/header.ejs, footer.ejs）

- ヘッダー：ロゴ（`/`へのリンク）、ナビゲーション（ホーム／カテゴリー／カレンダー／新規投稿）、検索フォーム（GET `/search`、`q`パラメータ、`searchQuery`で入力値を復元）
- `<title>`タグ：`<pageTitle> - JSON Blog`形式（`pageTitle`未指定時は`JSON Blog`）
- フッター：固定文言のみ

### 5.2 index.ejs（記事一覧／検索結果／カテゴリー別記事一覧）

| 表示項目 | データソース |
|---|---|
| 見出し | `heading` |
| 記事が0件の場合のメッセージ | `emptyMessage` |
| 記事カード（タイトル、投稿日時、投稿者、コメント数、カテゴリーバッジ、タグ、本文抜粋120文字＋省略記号） | `posts[]`, `commentCounts` |

### 5.3 post.ejs（記事詳細）

| 表示項目 | データソース |
|---|---|
| タイトル・投稿日時・投稿者・カテゴリーバッジ・タグ・本文全文 | `post` |
| 削除ボタン（確認ダイアログ付き） | フォームPOST `/posts/:id/delete` |
| コメント件数・コメント一覧（投稿者名・日時・本文） | `comments[]` |
| コメント投稿エラー表示 | `error` |
| コメント投稿フォーム（名前任意・本文必須） | フォームPOST `/posts/:id/comments` |

### 5.4 new-post.ejs（新規投稿）

| 表示項目 | データソース |
|---|---|
| エラーメッセージ | `error` |
| 入力フォーム（タイトル必須／本文必須／投稿者名任意／カテゴリー任意・既存候補を`<datalist>`表示／タグ任意カンマ区切り） | フォームPOST `/posts`、`categories`（候補一覧） |

### 5.5 calendar.ejs（カレンダー）

| 表示項目 | データソース |
|---|---|
| 年月表示・前月／翌月リンク | `year`, `month`, `prevYear`, `prevMonth`, `nextYear`, `nextMonth` |
| カレンダーグリッド（曜日ヘッダー、日付、投稿件数バッジ、本日強調、選択日強調） | `weeks[][]`, `todayStr`, `selectedDate` |
| 選択日の記事一覧 | `selectedDate`, `selectedPosts`, `commentCounts` |

### 5.6 404.ejs

| 表示項目 | 内容 |
|---|---|
| 固定メッセージ・ホームへのリンク | なし |

### 5.7 categories.ejs（カテゴリー一覧）

| 表示項目 | データソース |
|---|---|
| カテゴリーが0件の場合のメッセージ | 固定文言「まだカテゴリーがありません。」 |
| カテゴリー一覧（カテゴリー名へのリンク、記事件数） | `categories[]`（`{name, count}[]`） |

## 6. データ項目定義（物理設計）

### 6.1 data/posts.json

```json
[
  {
    "id": "1",
    "title": "string",
    "content": "string（改行\\nを含む）",
    "author": "string",
    "date": "ISO8601文字列 例: 2026-08-01T09:00:00.000Z",
    "category": "string（省略時は取得時に'未分類'として扱う）",
    "tags": ["string", "..."]
  }
]
```

### 6.2 data/comments.json

```json
[
  {
    "id": "1",
    "postId": "1",
    "name": "string",
    "message": "string",
    "date": "ISO8601文字列"
  }
]
```

### 6.3 ID採番規則

`nextId()`は対象配列内の`id`（数値変換）の最大値に+1した値を文字列として払い出す。記事とコメントのIDはそれぞれ独立した採番空間であり、相互に重複しても問題ない（`postId`で関連付けるため）。

## 7. エラー処理設計

| ケース | HTTPステータス | 挙動 |
|---|---|---|
| 存在しない記事IDへのアクセス（詳細／コメント投稿／削除） | 404 | `404.ejs`を描画 |
| 記事投稿でタイトル・本文が空 | 400 | `new-post.ejs`をエラーメッセージ付きで再描画（入力内容は再表示しない） |
| コメント投稿で本文が空 | 400 | `post.ejs`をエラーメッセージ付きで再描画（既存コメント一覧は再取得して表示） |
| 定義されていないURL・メソッド | 404 | `404.ejs`を描画 |

## 8. セキュリティ設計

| 対策 | 内容 |
|---|---|
| XSS対策 | 全てのユーザー入力値（タイトル・本文・投稿者名・コメント・カテゴリー・タグ・検索キーワード）はEJSの自動エスケープ出力`<%= %>`でのみ描画し、`<%- %>`（非エスケープ）は使用しない |
| 改行表現 | HTML注入を避けるため、本文・コメントの改行はサーバー側でHTML変換せず、CSS `white-space: pre-wrap`でブラウザ側に改行を保持させる |
| 入力サイズ制限 | フォームの`maxlength`属性でタイトル200字・投稿者名/コメント名50字を目安に制限（クライアント側制御。サーバー側の厳密なバイト長制限は本バージョンでは未実装） |
| ID指定によるアクセス | `id`は文字列比較のみで、SQLインジェクション等の問題は原理上発生しない（DB未使用のため） |

## 9. 今後の拡張に対する留意事項

- 同時アクセスによるファイル書き込み競合の排他制御（ロック機構）は未実装のため、高トラフィック環境へ拡張する場合は要検討。
- 認証・認可機能を追加する場合、`server.js`にミドルウェアを追加し、投稿・削除系ルートに適用する構成を想定。
- ページネーションを追加する場合は`db.getAllPosts()`の呼び出し元（`/`, `/search`）にオフセット・件数パラメータを追加する形で拡張可能。
