## 3. データアクセス層（lib/db.js）関数仕様

### 3.1 内部ユーティリティ

| 関数 | 引数 | 戻り値 | 処理内容 |
|---|---|---|---|
| `readJson(file)` | file: string（絶対パス） | Array | ファイルが存在しない／空の場合は`[]`を返す。存在する場合はUTF-8で読み込み`JSON.parse`する |
| `writeJson(file, data)` | file: string, data: Array | なし | `JSON.stringify(data, null, 2)`で整形しUTF-8で同期書き込み |
| `nextId(items)` | items: Array（id保持オブジェクト配列） | string | 既存要素の`id`（数値変換）の最大値+1を文字列で返す。空配列の場合は`"1"` |

### 3.2 記事関連関数

| 関数 | 引数 | 戻り値 | 処理内容 |
|---|---|---|---|
| `getAllPosts()` | なし | Post[] | `posts.json`全件を読み込み、`date`の降順（新しい順）にソートして返す |
| `getPostById(id)` | id: string\|number | Post \| null | 全件から`id`（文字列変換して比較）が一致する1件を返す。なければ`null` |
| `createPost({title, content, author, tags, category})` | 各string | Post | `nextId`でID採番。`title`/`content`は前後空白をtrim。`author`未入力時は`'匿名'`。`category`未入力時は`'未分類'`。`tags`はカンマ区切り文字列をtrim・空要素除去した配列に変換。`date`は`new Date().toISOString()`。`posts.json`に追記して返す |
| `deletePost(id)` | id: string\|number | なし | 該当`id`の記事を`posts.json`から除外して書き戻す。加えて`comments.json`および`reposts.json`から`postId`が一致するレコードを全て除外して書き戻す（カスケード削除） |
| `searchPosts(query)` | query: string | Post[] | クエリをtrim・小文字化。空文字なら`[]`。各記事本文からHTMLタグを除去（`p.content.replace(/<[^>]*>/g, ' ')`）した上で、`title + ' ' + content + ' ' + (category \|\| '') + ' ' + (tags \|\| []).join(' ')`を小文字化した文字列に対し`includes`で部分一致判定。一致した記事を新しい順（`getAllPosts`基準）で返す |
| `getPostsByDate(dateStr)` | dateStr: string（`YYYY-MM-DD`） | Post[] | `date`の先頭10文字（日付部分）が一致する記事を新しい順に返す |
| `getPostsByCategory(category)` | category: string | Post[] | `(post.category \|\| '未分類') === category`となる記事を新しい順に返す |
| `getCategories()` | なし | `{name, count}[]` | 全記事を`category`（未設定時`'未分類'`）ごとに集計。件数降順、同数はカテゴリー名の昇順（`localeCompare`）でソートして返す |
| `getPostsByTag(tag)` | tag: string | Post[] | `(post.tags \|\| []).includes(tag)`となる記事を新しい順に返す |
| `getTags()` | なし | `{name, count}[]` | 全記事の`tags`配列を展開し、タグ名ごとに件数を集計。件数降順、同数はタグ名の昇順（`localeCompare`）でソートして返す |

### 3.3 リポスト関連関数

| 関数 | 引数 | 戻り値 | 処理内容 |
|---|---|---|---|
| `createRepost(postId)` | postId: string\|number | Repost \| null | `getPostById(postId)`で記事存在確認。存在しなければ`null`。存在すれば`nextId`で採番し、`reposts.json`に`{ id, postId: String(postId), date: new Date().toISOString() }`を追記して保存し、repostオブジェクトを返す |
| `getRepostCounts()` | なし | Object（`{postId: count}`） | 全リポストを`postId`ごとに集計したオブジェクトを返す |
| `getFeedPosts()` | なし | Array | `posts.json`全件（`{ post, isRepost: false, sortDate: p.date }`）と`reposts.json`全件（元記事が存在すれば`{ post, isRepost: true, repostDate: r.date, sortDate: r.date }`）を統合し、`sortDate`降順（新しい順）でソートして返す |

### 3.4 コメント関連関数

| 関数 | 引数 | 戻り値 | 処理内容 |
|---|---|---|---|
| `getCommentsByPostId(postId)` | postId: string\|number | Comment[] | `postId`が一致するコメントを`date`昇順（投稿順）で返す |
| `addComment(postId, {name, message})` | postId, name: string, message: string | Comment | `nextId`でID採番。`name`未入力時は`'匿名'`。`message`はtrim。`date`は現在時刻ISO文字列。`comments.json`に追記して返す |
| `getCommentCounts()` | なし | Object（`{postId: count}`） | 全コメントを`postId`ごとに集計したオブジェクトを返す |

## 4. 認証層（lib/auth.js）関数仕様

| 関数 | 引数 | 戻り値 | 処理内容 |
|---|---|---|---|
| `verifyCredentials(id, password)` | id: string, password: string | boolean | 固定値（`ADMIN_ID`, `ADMIN_PASSWORD`）と文字列比較し、両方一致した場合のみ`true` |
| `parseCookies(header)` | header: string（`Cookie`ヘッダー値） | Object（`{name: value}`） | `;`区切りでパースし、各値を`decodeURIComponent`したオブジェクトを返す（非公開関数） |
| `isAuthenticated(req)` | req: Express Request | boolean | `req.headers.cookie`を`parseCookies`し、`session`Cookieの値が`SESSION_TOKEN`（`ADMIN_ID:ADMIN_PASSWORD`のSHA-256ハッシュ、固定値）と一致するか判定 |
| `login(res)` | res: Express Response | なし | `res.cookie('session', SESSION_TOKEN, { httpOnly: true, sameSite: 'lax' })`でログイン状態のCookieを発行 |
| `logout(res)` | res: Express Response | なし | `res.clearCookie('session')`でログイン状態のCookieを削除 |
| `requireLogin(req, res, next)` | Express標準のミドルウェア引数 | なし | `isAuthenticated(req)`が`true`なら`next()`。`false`なら`/login?redirect=<元のURL>`へ302リダイレクト |

- `SESSION_TOKEN`はサーバー起動時に固定のID・パスワード文字列から一度だけ算出される固定値であり、ログインごとに変化しない（単一の共有トークン方式）。複数ユーザーの識別やセッションの個別失効は行わない。

## 5. ルーティング詳細（server.js）

### 5.1 共通事項

- ミドルウェア：`express.urlencoded({extended: true})`（フォームPOST用）、`express.json()`、`express.static('public')`、`/tinymce`（`node_modules/tinymce`静的配信）、`/tinymce/langs`（`node_modules/tinymce-i18n/langs8`静的配信）
- ビューエンジン：EJS（`views`ディレクトリ）
- 共通ヘルパー：
  - `app.locals.formatDate(iso)` — ISO日時文字列を`ja-JP`ロケールの`YYYY/MM/DD HH:mm`形式に整形し、全テンプレートから`formatDate()`として利用可能にする
  - `app.locals.stripHtml(html)` — HTML文字列からタグ（`<[^>]*>`）および実体参照を除去し、連続空白を単一スペースに正規化した平文テキストを返し、全テンプレートから`stripHtml()`として利用可能にする
  - `wrapPosts(posts)` — 通常記事配列を`{ post, isRepost: false, sortDate: post.date }`の配列（`items`形式）にマッピングする内部ヘルパー
  - `escapeXml(str)` — XML特殊文字（`&`, `<`, `>`, `"`, `'`）を実体参照（`&amp;`, `&lt;`, `&gt;`, `&quot;`, `&apos;`）に置換する内部ヘルパー
- 共通ミドルウェア：全リクエストに対し`res.locals.isAuthenticated = auth.isAuthenticated(req)`を設定し、全テンプレート（`partials/header.ejs`のログイン／ログアウト表示切り替え、`index.ejs`/`post.ejs`のリポストボタン表示切り替え等）から`isAuthenticated`として参照可能にする

### 5.2 GET `/` — 記事一覧

### 5.3 GET `/rss.xml` — RSSフィード配信

| 応答ヘッダー | `Content-Type: application/rss+xml; charset=utf-8` |
| 応答形式 | XML文字列（RSS 2.0） |

## 6. 画面詳細設計

### 6.1 共通パーツ（partials/header.ejs, footer.ejs）
- ヘッダー：ロゴ（`/`へのリンク）、ナビゲーション（ホーム／カテゴリー／タグ／カレンダー／新規投稿／RSSボタン（`.rss-button`、SVGアイコン＋テキスト、`/rss.xml`へのリンク））、検索フォーム（GET `/search`、`q`パラメータ、`searchQuery`で入力値を復元）
- ログイン状態表示：`isAuthenticated`が`true`の場合はナビゲーション末尾に「ログアウト」ボタン（フォームPOST `/logout`）、`false`の場合は「ログイン」リンク（`/login`）を表示
- `<title>`タグ：`<pageTitle> - JSON Blog`形式（`pageTitle`未指定時は`JSON Blog`）
- `<head>`内RSS auto-discovery：`<link rel="alternate" type="application/rss+xml" title="JSON Blog RSS" href="/rss.xml">`を配置
- フッター：固定文言のみ

### 6.2 index.ejs（記事一覧／検索結果／カテゴリー別記事一覧）

| 表示項目 | データソース |
|---|---|
| 見出し | `heading` |
| 記事が0件の場合のメッセージ | `emptyMessage` |
| リポストバナー | `item.isRepost`が真の場合、`item.repostDate`（`formatDate`で整形） |

### 7.4 ID採番規則

`nextId()`は対象配列内の`id`（数値変換）の最大値に+1した値を文字列として払い出す。記事・コメント・リポストのIDはそれぞれ独立した採番空間であり、相互に重複しても問題ない（`postId`で関連付けるため）。

## 8. エラー処理設計

| ケース | HTTPステータス | 挙動 |
|---|---|---|
| 存在しない記事IDへのアクセス（詳細／リポスト／コメント投稿／削除） | 404 | `404.ejs`を描画 |
| 記事投稿でタイトル・本文が空 | 400 | `new-post.ejs`をエラーメッセージ付きで再描画（入力内容は再表示しない） |
| コメント投稿で本文が空 | 400 | `post.ejs`をエラーメッセージ付きで再描画（既存コメント一覧は再取得して表示） |
| 未ログインで`/new`, `/posts`, `/posts/:id/repost`へアクセス | 302 | `/login?redirect=<元のURL>`へリダイレクト |
| ログインでID・パスワードが不一致 | 400 | `login.ejs`をエラーメッセージ付きで再描画 |
| 定義されていないURL・メソッド | 404 | `404.ejs`を描画 |

## 9. セキュリティ設計

| 対策 | 内容 |
|---|---|
| XSS対策 | 記事詳細画面（`post.ejs`）ではTinyMCEで生成されたリッチテキストHTMLを表示するため`<%- post.content %>`で非エスケープ描画する。タイトル・投稿者名・コメント本文・カテゴリー・タグ・検索キーワード等のその他の入力値はすべてEJSの自動エスケープ出力`<%= %>`でのみ描画する |
| XMLインジェクション・構文エラー防止 | RSSフィード（`GET /rss.xml`）生成時、記事タイトル・リンク・GUID・投稿者・抜粋テキストの各値に対して`escapeXml`（`&`, `<`, `>`, `"`, `'`の実体参照置換）を適用し、不正なXML構造の生成やインジェクションを防止する |
| 改行・レイアウト表現 | 記事本文はTinyMCEによるHTMLタグ（`p`, `ul`, `ol`, `blockquote`等）で構造化され、CSSで適切なマージン・引用スタイルが適用される。コメント本文は改行文字（`\n`）のまま保持されCSS `white-space: pre-wrap`で改行を表示する |
| 入力サイズ制限 | フォームの`maxlength`属性でタイトル200字・投稿者名/コメント名50字を目安に制限（クライアント側制御。サーバー側の厳密なバイト長制限は本バージョンでは未実装） |
| ID指定によるアクセス | `id`は文字列比較のみで、SQLインジェクション等の問題は原理上発生しない（DB未使用のため） |
| ログイン認証 | ID・パスワードは`lib/auth.js`内の固定値（`ADMIN_ID`, `ADMIN_PASSWORD`）と単純な文字列比較で検証する。パスワードのハッシュ化・複数アカウント・ロックアウト（試行回数制限）は本バージョンでは未実装 |
| セッションCookie | ログイン状態を表すCookieには`HttpOnly`（JavaScriptからの読み取り防止）・`SameSite=Lax`（他サイトからの送信制限）を付与する。`Secure`属性は付与していないため、HTTPS配信環境で運用する場合は追加を検討すること |
| セッショントークン | 固定のID・パスワードから算出した単一の固定トークンを全ログインで共有する方式であり、ユーザーごとの個別セッション管理・強制ログアウト・トークン失効の仕組みは持たない |

## 10. 今後の拡張に対する留意事項

- 同時アクセスによるファイル書き込み競合の排他制御（ロック機構）は未実装のため、高トラフィック環境へ拡張する場合は要検討。
- 複数アカウント対応（ユーザーごとのID・パスワード管理、権限区分）を追加する場合、`lib/auth.js`をファイルベースまたはDBベースのユーザーストアに置き換える構成を想定。現状は固定の単一管理者アカウントのみ。
- 記事削除（`POST /posts/:id/delete`）には現時点でログイン必須化を適用していない。管理者操作として保護対象を広げる場合は`auth.requireLogin`を追加する。
- ページネーションを追加する場合は`db.getAllPosts()`や`db.getFeedPosts()`の呼び出し元（`/`, `/search`）にオフセット・件数パラメータを追加する形で拡張可能。
